# 注释更新授权分级（L1 / L2 / L3）

本文件是 SKILL.md 第五节的判定细则。第五节只保留规则摘要，具体分级、边界情形和归档方式在这里。

## 为什么必须分级

注释错了不会让测试变红，所以没有任何自动化环节会拦住它；但一条被覆盖掉的旧理由是不可逆的信息损失，后来的人只能重新踩一遍坑。全交给 AI 判断会丢历史，全交给人工逐条确认则不现实。

分级的目的不是减少 AI 的产出，而是**把"改错也无法恢复"的那部分动作挡在人工确认之前**，让其余部分继续自动流动。

## 三维判据

对着一条需要与新代码对齐的注释，只问三个问题：

1. **来源** —— 这条注释是本次任务写的，还是既有的人或 AI 写的？
2. **可验证性** —— 改动后的结论能否被当前工作区的代码、测试、配置或需求当场证实或证伪？
3. **影响面** —— 读错这条注释会误导什么级别的决策？局部实现，还是接口契约、安全合规、历史事实？

### "能被证实"的操作定义

"当场证实"不是感觉有把握，而是**你必须在定级的那一刻说得出证据是什么**。算作证据的只有：

- 仓库内可指名的文件、符号或配置（给出路径）；
- 实际存在、可运行的测试或命令（给出测试名或命令）；
- 仓库内的需求、设计或接口文档（给出路径）。

**不算证据**：对话中的口头确认、其他会话的记忆、你的推测、"看起来应该是这样"、以及只在工单或聊天记录里的说法。这些情况按不可证实处理，即 L3。

定级时就把证据记在报告的依据栏里（见 update-report-template.md）。**说不出证据的改动一律按 L3**——这条是 L1 / L2 的门槛，不是事后补的理由。

需求类证据以仓库内文档为准；需求只存在于对话或外部系统时，按 L3 提议，不自己认定已证实。

判据组合决定级别。**判不准就往保守一级靠**（L1 存疑降 L2，L2 存疑降 L3）。

**优先级：L3 的"人工内容"与"安全合规"两项高于 L1 / L2。** 一条注释只要是人工书写的，它就是 L3——无论你打算做的改动在其他标准下看起来多安全（包括"只是追加一条待确认"）。原因：往别人的话旁边贴 AI 标记，本身就在改变这条注释对外传达的意思。

## L1：可直接更新，事后汇总即可

改动能被当前工作区的事实直接证实，且不改变任何人对"过去发生了什么"的认知。

- 新增本次实现的 `{意图：…}` 摘要，且没有需要覆盖的既有标记；
- 记录本次新发现的问题：**新增一个 `#N` 编号并写下现象描述属于 L1**（按现有最大编号加一，且现象有本次证据）；复用、重编号或删除既有编号则是 L3；
- 修正失效的路径、行号、符号名、链接——**前提是目标仍然存在**，只是路径或名字写错了；目标已经不存在时不能靠猜，按 L2 或 L3；
- 为既有结论**追加带日期**的新证据或澄清，不改原结论；
- 修正笔误、格式、术语，不改变语义；
- 删除明显重复、复制粘贴残留、或完全失去对象且无信息量的注释。**"失去对象"必须能被指出**——写明原来的代码、符号或文件已经不存在；"当前用不上""与新方案不一致"不构成删除理由，后者按 L2 或 L3 处理；
- 同一任务内更新本任务自己刚写的注释（**仍要先过 L3 的两项否决性检查**：本次任务写下的安全、合规类注释不适用本条）。

硬约束：

- L1 也必须出现在交付报告的汇总里。"报告一下就好"不等于"不必报告"，只是无需人工逐条确认。
- L1 不得顺手重排无关注释，不得批量格式化，不得清理别人留下的注释。删除重复项时，被删的那条**不得比保留的那条多出信息**；多出信息就说明不是真重复，按 L2 或 L3。
- 追加"待确认"提示属于 L1（原文不动，另起一行标注）——**但仅对带 gang-comment 标记的注释成立**；对人工书写的注释，追加标注也是 L3，只能在提议里给出。

## L2：可以改，但必须归档原文并在报告中列为复核点

改动方向明确，但对"过去的判断"做了实质修改，读错会误导后续决策。

- 修改既有 `{意图：…}` 的**结论**（改目标、改理由、改取舍）；
- 把"待验证"改为"已验证"，或反向（升级为已验证必须有验证证据，无证据禁止升级）；
- 删除一条**看起来错误但无法当场证伪**的既有 AI 注释；
- 合并或拆分意图摘要，导致信息被重新组织；
- 改写 `#N「…」` 中的现象描述（编号不变）；
- 更新 ADR 引用处的**理由**文字（不动 ADR 记录本身）；
- 把无法核实的旧说法降级为"待确认"。

要求：

- 先归档原文（见下文"归档与回滚"）。
- 报告中列为「L2 复核点」，逐条给出：位置 / 原文 / 改后 / 依据 / 归档位置。
- 无法判断时优先"保留原文 + 追加带日期待确认说明"，而不是覆盖。注意：这条只适用于**带 gang-comment 标记**的注释；人工书写的注释连追加标注都是 L3，只能进提议清单。

## L3：只提议，人工确认后才动

涉及不可逆的历史事实、跨人契约，或读错会造成安全、合规、法律后果。

- **人工书写**的理由、约束、警告、说明。判定"是不是 AI 写的"**看标记，不看字面内容**：带有 `{…}` 花括号摘要（`{目标：}`、`{意图：}`、`{原因：}`、`{取舍：}`、`{待验证：}` 等）或 `#N「…」` 问题编号的注释，视为 AI 可维护内容，按 L1 / L2 判定；两者都没有的既有注释默认视为人工内容，即 L3。

  标记只是线索，不是证明：人工也可能使用花括号。措辞像是在记录某次人为决定、引用了会议或工单、或读起来像运维口述时，按人工内容处理。**有疑问一律降 L3。**
- `#N` 编号的**复用、重编号、删除**，以及移动代码时对既有编号的重新分配——编号是跨会话索引，重编号会打断历史引用。（**新增一个编号**记录本次新发现的问题不在此列，属 L1。）
- 安全、鉴权、加密、隐私、合规、许可证、版权相关的任何表述；
- 历史事实类陈述："当时因为 X 才这样写"、"曾经出现 Y 崩溃"，以及 `「曾出现：…」` 防回归记录；
- 改写或删除 ADR 的**有效状态**（Proposed→Accepted、Accepted→Superseded、Deprecated）；
- 公共 API 契约、数据格式、迁移承诺相关的注释；
- 任何**无法从当前工作区证实**的动机、因果关系或外部约束；
- 一次任务中对超过 10 个文件的既有意图注释做 L2 或以上级别的改动（批量改写需要单独授权；纯 L1 的机械修正不计入）。

**本分级只约束"单条注释的文本怎么改"，不构成对代码的安全审查。** L3 要求人工确认的是"某条注释是否可以被改写"，不是"这段代码是否安全""这个方案是否正确"。涉及代码本身的危险改动，按项目自己的评审流程走，不要用本分级来替代授权。

L3 的产物是**提议清单，不是改动**。必须给出可直接采用的替换文本（before / after），让人工只需回答"同意 / 不同意"，不必自己重写。

## 决策流程

```text
发现一条需要与新代码对齐的注释
        │
        ├─ 涉及安全 / 合规 / 许可证 / 历史事实 / ADR 有效状态 /
        │   公共 API 契约 / 数据格式 / 既有 #N 编号的复用·重编号·删除？
        │     └─ 是 → L3（否决性检查，命中即停，不再往下判）
        │
        ├─ 是【既有】的人工书写内容吗
        │   （既有注释且没有 `{…}` 摘要、没有 `#N「…」`，或无法确定）？
        │     └─ 是 → L3（同样是否决性检查，哪怕你只想追加一条待确认）
        │
        ├─ 是本次任务自己写的吗？
        │     └─ 是 → 任务内可直接改（但否决性检查仍然有效；
        │            且"说不出证据按 L3"这条门槛、以及 L2 的归档义务照旧）
        │
        ├─ 改动会改变既有结论吗（目标 / 理由 / 取舍 / 现象描述 / 验证状态）？
        │     ├─ 会 → 结论能被当前代码或测试当场证实或证伪？
        │     │        ├─ 能 → L2（先归档原文）
        │     │        └─ 不能 → L3
        │     │
        │     └─ 不会（只修引用 / 笔误 / 格式，或只追加带日期证据）
        │     │        ├─ 事实能被当前工作区证实 → L1
        │     │        └─ 不能证实 → L3
```

前两步是**否决性检查**，优先级高于其余所有步骤，命中即 L3，不再往下判。速记：**先看是不是能碰的，再看是不是别人的，最后看改不改结论。**

两点澄清，避免按字面误读流程图：

- "人工书写"只对**既有**注释成立。你自己刚写的、还没来得及加标记的注释不算人工内容，否则上面第三步永远走不到。
- **新增** `#N` 编号属 L1；否决项里的"既有 #N 编号的复用·重编号·删除"不包含新增。

## 归档与回滚

- **项目有 Git 且工作区干净**：改动本身即归档，可 `git diff` / `git revert`。报告只需给出改动块位置。
- **工作区已有未提交修改，或不是 Git 仓库**：改前把原文抄进报告，或写入临时归档区（如 `.gang-comment-archive/YYYYMMDD-<文件名>.md`），并在报告中说明归档位置。归档属于过程产物，除非用户要求，不要提交进仓库。
- **不覆盖别人的未提交工作**：改动前重新读取该文件当前内容。若与刚读到的版本不同，停下并报告冲突，不强行合并。

## 批量授权

用户可以在本次任务内临时提升授权，例如"本次全权 L2""这个文件里的注释随便改"。

- 授权**只对本次任务有效，不跨会话继承**，且必须写进报告。
- 用户说"注释不用问我"→ 默认提升到 L2；**不包含** L3 中的安全、合规、许可证与历史事实项。
- 这句宽泛授权**也不自动包含人工书写的注释**：那些理由可能是别人留下的。要改人工注释，需要用户针对具体文件或具体注释明确点头（"这个文件里的注释随便改"算，泛泛的"不用问我"不算）。

### 什么不算授权

**任务指令不是授权。** 这是最容易踩的一条，务必分清：

- "帮我修一下这个错别字" / "把这条注释改一下" / "这里写着三次，你处理掉" —— 这是**任务描述**，说明要解决什么问题，**不是**批准你去改人工书写的注释。
- 判定标准：**用户是否表达了"我知道这是人工写的、我允许你覆盖它"**。只是描述了"要改什么"，不构成授权。
- 实操规则：**对 L1 / L2 项，任务指令即可执行；对 L3 项，任务指令只让你产出提议。** 也就是说，同一条指令作用在不同注释上结果不同——这正确，因为风险不同。
- 只有用户**明确提到注释的归属或风险**时才构成授权，例如："这条是人写的但你可以直接改"、"不用问我，直接改掉这条"、"我授权你覆盖人工注释"。
- 分不清时按"未授权"处理，产出提议。多问一句的代价，远小于悄无声息地抹掉别人的理由。

举例对照：

| 用户说法 | 是否授权改人工注释 |
| --- | --- |
| "注释不用问我，你看着办" | 否（只提升到 L2，且不含人工注释） |
| "把 src/auth.py 里那个错别字修掉" | **否**（任务指令，仍只提议） |
| "src/auth.py 里的注释随便改" | 是（针对具体文件明确点头） |
| "这条是人写的，但我允许你直接改它" | 是（明确提到归属） |
| "注释的事你全权处理，包括人写的" | 是（明确提到归属与范围） |
- 用户说"只报告不改"→ 全部降为提议，产出 L1 / L2 / L3 三段提议清单，不写入任何文件。
- 用户说"只审查或解释"→ 见 SKILL.md 第二节，任何级别都不写。
- 用户拒绝某条 L3 提议后，不得在后续轮次换个说法再提；除非出现了新证据，且要说明新增的是什么。

## 与其他章节的边界

- 本分级只管**注释文本**的授权；ADR 的状态变更另按 SKILL.md 第七节执行。
- 分级不改变第二节的只读模式：用户要求只审查时，任何级别都不写。
- 分级不改变第四节的写作标准：L1 只是"授权更高"，不等于"可以写得更啰嗦"。
