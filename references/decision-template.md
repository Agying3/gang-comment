# ADR 最小模板

仅在项目没有既有模板且本次获准创建 ADR 时使用。尖括号内容是待填写提示，不要原样留在最终记录中；不适用的可选项直接省略，不编造历史或备选方案。

## 状态与历史

- Proposed 是提案，不能因此把现行记录改为 Superseded。
- 新决策已被接受且明确取代旧决策时，才将旧记录标为 Superseded，双方互链。
- Accepted 表示决策获接受，不代表代码上线或迁移已完成；实施情况另写。
- 保留原记录日期，状态变化记实际日期。补录历史而无法确认决策日期时，标为未知，不倒填日期。
- 修正链接或事实错误可以保留原编号；重大决策变化另建记录，不改写旧决定的背景与理由。

```markdown
# ADR-NNNN：<决策名称>

- 状态：<Proposed / Accepted / Superseded / Deprecated，选择一项>
- 记录日期：<YYYY-MM-DD>
- 决策依据：<用户确认、决策记录等；尚未确认则写明>
- 实施情况：<未实施、试验中、迁移中、已实施等，按事实填写>
- 关联记录：<可选；注明提案关联、替代或被替代关系，并提供链接>

## 背景与证据

<要解决的问题、必要约束，以及可核验的代码、测试、需求或讨论依据。区分事实和未验证假设。>

## 决策

<采用或提议采用什么方案、适用范围，以及不能破坏的约束。>

## 备选方案

<只写实际考虑过或有证据的替代方案与取舍；没有记录时如实说明，不编造过去的评估。>

## 后果与风险

<收益、成本、限制，以及需要跟进或复查的条件。>

## 受影响代码

- <路径或符号>：<它如何依赖此决定>

## 变更记录

<可选；后续状态变化或重要澄清按日期追加，保留原始决定。>
```
